How to run a setlist from a Pro Tools session

Pro Tools has no setlist. It has a timeline, and a list of memory locations, and an operator who has learned to read one as the other. That works — plenty of shows run this way every night — but it is a skill held in one person's head, and it fails in a specific and predictable way: the night the set changes at 4pm and nobody re-reads the markers.

This is how to build a setlist inside a Pro Tools session that survives that night. No plug-in, nothing to buy, nothing you can't do this afternoon.

First: pick one session, not one session per song

Three layouts show up in the wild.

One session, all songs on one timeline. Every song laid end to end, separated by markers. Load once at soundcheck, never load again. Jumping between songs is a locate, which is instant.

One session per song. Clean to edit, terrible live: opening a session takes seconds you do not have, closes your outputs, and drops your hardware inserts and I/O for the duration. It also means your click routing and stem outputs have to be identical across dozens of files, and one wrong I/O setup is a silent song.

One session, playlists per song. Occasionally used for shows with alternate arrangements, but it multiplies the number of places a mistake can hide.

For live playback, use the first one. Everything below assumes it.

Leave the songs in a fixed order on the timeline. Resist the urge to physically drag audio around when the running order changes — you will do it at 5pm with the band waiting, and you will nudge something. The running order is a decision about what you locate to next, not about where the audio lives.

The marker convention is the whole job

The markers are the setlist. If they are readable at a glance under pressure, you have a setlist. If they say Marker 47, you have a liability.

A convention that works, in order of how much it buys you:

  1. A number, a title. 01. Midnight Run. Two digits, always — 1. and 10. sort differently in every list you will ever look at, and two digits keeps them aligned. The number is also how the band and MD will talk to you: "start from seven."
  2. Tempo and key, if the band uses them. 01. Midnight Run / 120 / Am. Cheap to add, and it means the one screen you look at during a talk break has the answer to the question you are about to be asked.
  3. An explicit end marker per song. SongEnd, right on the downbeat where playback should stop. This one gets skipped most often and costs the most. Without it, "where does this song end" is a judgement call made live.

The important property is not the exact punctuation — it is that a machine, or a stranger covering your shift, could parse it without asking you. Pick a convention, write it at the top of the session notes, and never mix two.

Since Pro Tools 2023.6 you can also colour memory locations. Use it as a second channel, not the primary one: songs one colour, encores another. Colour is fast to scan and impossible to search, so it should confirm the naming, never replace it.

Keep the sections off the marker list

The instinct is to add a marker for every verse and chorus too. Resist it. A twenty-song set is twenty song markers and twenty end markers; add sections and you have two hundred rows in a scrolling window, where the one marker that got dragged is invisible until the downbeat.

Put the section map on a track instead. Add one audio track, call it Sections, and drop a short silent clip at the start of every section named for that section — Intro, Verse 1, Chorus 1. You now read the shape of a song the way you read everything else in the edit window: horizontally, in place, at the position it actually occupies. Renaming a clip is a double-click, moving one is a drag, and a clip that ends up in the wrong place is visible from across the room instead of being row 143 of a list.

The rule that keeps it honest: every section clip belongs strictly between a song's start marker and that song's end marker. A clip stranded in the gap between two songs belongs to neither.

Recall, and the properties that will bite you

Every memory location stores more than a position. When you create one, Pro Tools offers to capture zoom settings, pre/post-roll, track visibility, track heights, group enables and a window configuration.

For a show session, capture none of them. A marker that also recalls track heights will rearrange your edit window in front of you mid-show, and the first time it happens you will think the session is corrupt. Make your show markers position-only, and audit the ones you inherited from the production session — those almost always carry properties from someone's editing setup.

For recall itself, get comfortable with the numeric keypad rather than the mouse. The exact keystroke depends on Setup → Preferences → Operation → Numeric Keypad Mode, so check which mode the show Mac is in, set it once, and rehearse it.

Three settings that stop the session moving when you don't want it to

These are the ones that separate a show session from an edit session.

Unlink the timeline and edit selections. With Options → Link Timeline and Edit Selection off, clicking in the edit window to look at something no longer moves where playback will start. This single toggle prevents a whole family of accidents.

Decide about Dynamic Transport before the show, not during it. It is genuinely useful for jumping between songs, and genuinely confusing if half the crew doesn't know it's on. Pick one and put it in the session notes.

Turn off anything that writes. Auto-backup during a show buys you nothing — the session isn't changing — and costs you a disk hiccup at a random moment. Save your show state at the end of soundcheck and stop saving.

The part nobody has a good answer for: the running order changed

This is where the paper setlist and the session diverge, and it is the actual failure mode.

The set changes at soundcheck. Song 9 moves to the encore, two songs get cut, one gets added back from last tour. Your options in stock Pro Tools:

  • Renumber the markers. You now have 01…, 02… that no longer match the printed setlist the band is holding, or you renumber those too. Twenty minutes, in the dark, while someone waits.
  • Leave them and keep a paper cheat sheet taped to the desk mapping "printed 4 = marker 09." This is what most people actually do. It works until you look up.
  • Rebuild nothing and just remember. Works for three shows. Does not work on the fourth, at the end of a long run, when you are covering for someone.

Whatever you choose, adopt one rule: the Pro Tools markers are the source of truth for where the audio is, and the running order is a separate document. The moment you start editing marker names to express the running order, you have two sources of truth that will disagree, and one of them will be right in the dark.

An honest pre-show audit, in five minutes

Do this every load-in, out loud, before you switch to show discipline:

  1. Song count in the Memory Locations window against the count on the printed setlist.
  2. Every song has an end marker. This is the one that gets missed.
  3. No duplicate numbers, no duplicate titles.
  4. Every clip on the Sections track sits between a song start and that song's end — a clip stranded in a gap is a sign something got dragged.
  5. Tempo written on the marker matches the tempo the band actually plays. If a marker says 120 and the track measures 95, one of them is a typo, and it is usually the marker.

Five minutes. It catches almost everything that would otherwise be discovered at the downbeat.

Automating it

Everything above is manual, and it is meant to be — a rig you can run by hand is a rig you can rescue by hand.

The part that does not automate well by hand is the last two sections: keeping the running order separate from the markers, and re-auditing after every change.

That is the specific job we built Prossible for. It reads your memory locations and your Sections track over PTSL, builds a setlist from exactly the convention above, and lets you drag the running order into tonight's shape inside the app — your markers, clips, numbering and colours are never touched and nothing is written back to the session. It re-runs the audit above on every resync and lists what it found: missing end markers, duplicate numbers, section clips outside any song, tempo that doesn't match the measured length. It does not install anything into Pro Tools; there is no plug-in and no script.

Requirements are narrow on purpose: macOS 15 or later on Apple silicon, on the same Mac as Pro Tools 2023.6 or later with PTSL.
